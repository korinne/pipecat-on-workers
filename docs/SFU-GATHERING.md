# SFU gathering failure and correction

The user reported “WebRTC could not gather a network route. Try another network or the WebSocket example.” in the SFU example on their laptop, using Chrome with headphones. [Original report](../evidence/sfu-gathering-20261005/user-report.json). This is a failed connection-setup check; it did not establish usable SFU media or physical playback. The loaded asset revision and network type were not observed.

The message came from an unconditional eight-second wait for `iceGatheringState === complete`. That could discard candidates already found while another STUN lookup remained pending. Cloudflare's [current guide](https://developers.cloudflare.com/realtime/sfu/get-started/connection-patterns/#network-connectivity) links a [pinned helper](https://github.com/cloudflare/realtime-examples/blob/5a3960ce7d98c1f8d452ba5f506a7520f10c57a0/cloud-gaming/src/client/webrtc.ts#L31-L62) that permits negotiation with candidates already present at its deadline. Its example uses ten seconds; this application retains its existing eight-second bound. [Primary-source review](../audit/results/sfu-gathering-contract-20261005.json).

Commit `3f62b68` now sends the current local description if gathering completes, or if its deadline arrives with a candidate already present. A timed-out gather with no candidates still fails. Both microphone publishing and output answering use this path. Candidate presence permits a connection attempt; the original connected-state and track checks still gate `input_ready` and `playback_ready`. End and replacement cancel the waits, and late work cannot signal readiness for a retired peer. No TURN credentials, network settings, models or user-turn policy changed.

The [before-fix reproduction](../audit/results/sfu-gathering-before.json) preserves two failing cases. After the correction, [73 browser tests](../audit/results/sfu-gathering-fixed.json) passed, including 24 SFU tests. The [independent review](../audit/results/sfu-gathering-independent-20261005.json) verified final boundary/cancellation cases and confirmed that `public/sfu-client.mjs` is the only changed runtime file compared with the previous deployment. All Python and dependency/configuration files match.

A separate [native Mac STUN probe](../evidence/sfu-gathering-20261005/native-stun.json) received valid IPv4 and IPv6 binding replies. It did not use Chrome, and cannot establish Chrome's network permissions, candidate gathering or SFU media reachability. No addresses, SDP, transaction identifiers or credentials were retained. Browser automation was unavailable, so it cannot substitute for the user's retry.

The correction is deployed from `3f62b680c32afa8b9f343a4eafb95d34b32c9daa` as `06111df0-88ce-4142-96e7-4158a9a6e7a9`. The [served asset](../evidence/sfu-gathering-20261005/deployed-asset.json) matches the tested hash and uses `max-age=0, must-revalidate`. One [direct provider regression](../evidence/sfu-gathering-20261005/direct-provider-regression.json) passed after deployment: one final user transcript, one assistant sentence, 130 audio chunks with timed software receipts, and zero tracked local resources after End. It does not exercise SFU media. Immediate rollback is `4d75ac46-5a71-4de4-aa12-26f8b026fc38`. [Deployment record](../evidence/deployment-sfu-gathering-06111df0.json).

The requested Chrome retry is pending. SFU media and physical playback remain untested after the correction; the original setup failure remains recorded. The WebSocket follow-up failure and pending silence-policy choice are separate. Performance acceptance remains deferred.
